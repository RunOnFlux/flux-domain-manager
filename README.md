# Flux Domain Manager

![Flux.png](https://raw.githubusercontent.com/RunOnFlux/flux/master/flux_banner.png)

Flux Domain Manager (FDM) manages domains, certificates and load balancing for entire Flux network as well as for applications running on Flux network. FDM in its basics is HAProxy configurator connected to Flux network.

Flux Team is running FDM on runonflux.io domain and is automatically managed on cloudflare and pDNS solution. Anyone can stand up its own FDM on any domain with default settings providing own cloudflare API keys or pDNS keys.

FDM scans Flux network, every healthy node on Flux network is put into FDM for both HOME.yourroot.domain (providing UI) and API.yourroot.domain (providing API endpoints to entire Flux).

Furthermore FDM load balances all applications running on Flux network putting them begind YOURAPPNAME.app.yourroot.domain. If an application has more ports, applications lives on YOURAPPNAME_PORT.app.yourroot.domain in order of how ports were registered on Flux application specifications.

Enable `automateCertificatesForFDMdomains` flag in config if you want certificate management to be happening for automated domains generated by FDM. Default false.

Enable `automateCertificates` flag in config if you want certificate management to be happening for custom domains set by an application. Default true.

domainAppType: 'CNEME' or 'A'
- FDM can create either CNAME records or A record of an application. In case of using CNAME record type (default), records will be pointed to fdmAppDomain.

-   provide domain

## Wildcard application routing

An operator can bind a site namespace to one application's existing HTTP backend:

```js
wildcardAppRoutes: [
  {
    domain: 'drop.runonflux.io',
    appName: 'drop',
    targetDomain: 'drop.app.runonflux.io',
  },
],
```

`domain` is the namespace without `*.`. `appName` is the Flux application name,
and `targetDomain` selects the exact HTTP endpoint from FDM's discovered app
configuration. A generated per-port domain such as `drop_31512.app.runonflux.io`
can select a specific component/port. FDM resolves the public port and healthy
instances dynamically; no IPs or container ports belong in this setting.

Standalone config defaults to `[]`. The Ansible template enables the binding
above for production application FDMs (`manageApps=true`, `appSubDomain=app`),
including their certificate manager. Staging and main-network FDMs default to
`[]`. Set the Ansible variable `wildcardAppRoutes` to override the bindings;
explicit `[]` disables them. An invalid, overlapping or recursive binding is
rejected. TLS/TCP targets and ambiguous target endpoints are also rejected.

Only one valid DNS label is routed: `hello.drop.runonflux.io` works, while the
namespace apex, nested names, invalid labels and labels over 63 characters
return 404. Host matching accepts uppercase, an explicit port and a trailing
DNS dot. The **original** Host header, path, query, method and body reach the
application unchanged. HTTP requests retain FDM's existing HTTPS redirect and
ACME handling. Global forbidden-host/path rules still take priority.

The complete namespace is reserved against applications' custom-domain claims,
including DNS/certificate provisioning. If the target is missing, has no healthy
instances, or is outside this FDM's app subset, valid site hostnames return 503;
they never fall through to another application's custom-domain backend.

For Flux Drop, point a wildcard CNAME `*.drop.runonflux.io` to the **same FDM
pool** serving `drop.app.runonflux.io`. Do not point it to a different subset or
to Drop's individual nodes. FDM terminates TLS and uses plain HTTP to the
application's published Flux port, including IPv6 instances. No certificate is
needed inside the application container.

Install the certificate, intermediate chain and matching private key as one PEM
at `/etc/ssl/fluxapps/drop.runonflux.io.pem` (or the configured `certFolder`).
Protect the private key with permissions compatible with HAProxy and your
certificate-sync account. HAProxy loads this directory and selects by SNI.
Install at the authoritative certificate-sync source, then distribute to **all**
FDMs in the serving pool: the existing rsync uses `--delete`, so files installed
only on a receiving peer can disappear. After installation and each renewal,
validate and reload HAProxy on every recipient:

```sh
sudo haproxy -c -f /etc/haproxy/haproxy.cfg
sudo systemctl reload haproxy
```

Wildcard ACME certificates require DNS validation; this binding does not issue
certificates or create wildcard DNS records. `*.drop.runonflux.io` does not cover
`drop.runonflux.io` itself. Cloudflare-proxied records also need an edge
certificate covering the deeper wildcard and Full (strict) to FDM. A Cloudflare
Origin CA certificate works on FDM only when browsers connect through Cloudflare;
DNS-only records need a publicly trusted FDM certificate. Preserve the original
Host in Cloudflare rules.

Drop itself must implement hostname-based project delivery before these URLs
serve projects. This FDM change does not rewrite `/` into `/hello/`, enable
custom project domains, or change Drop's browser sandbox.

Run `npm test` and `npm run lint` for unit checks. With Docker and OpenSSL,
`npm run test:wildcard` validates and runs the generated HAProxy configuration
with temporary loopback listeners, a test wildcard certificate and local HTTP
backends. It checks TLS/SNI, IPv4/IPv6 HTTP upstreams, forwarding, balancing,
namespace protection, unavailable targets and existing exact-host routing.
`FDM_TEST_HAPROXY_IMAGE` can select another HAProxy version. Test containers and
certificate files are removed afterward; no live Flux or Cloudflare access is
used.

## Operator alerts

FDM posts to a Discord webhook when it keeps the current haproxy config instead of publishing a new one:

- `spec-refused` - the app spec list from the Flux API was malformed, or more than 30% smaller than the last accepted one, for longer than 2 minutes
- `config-refused:G` / `config-refused:nonG` - a config pass computed a half more than 30% smaller than the one it last published, for longer than 2 minutes

A list more than 30% smaller than the last accepted one, an empty list included, is published once every result for 10 minutes has been that small. With nothing accepted before, a list needs at least 5 entries, or the same 10 minutes. The last accepted sizes are kept in `/var/lib/flux-domain-manager/list-guards.json`, so a restart is judged against them.
- `haproxy-reload` - three consecutive reloads did not bring up a new haproxy worker; the message names each port that failed to bind and the socket holding it

Each condition sends one message when it starts and one when it clears. Set `alerts.discordWebhookUrl` in config. The ansible playbooks render it from the `DISCORD_WEBHOOK_URL` environment variable, which the deploy workflow sets from the repository secret of the same name; `-e discord_webhook_url=...` overrides it for a manual run. It never goes in a tracked file. Empty sends nothing. Thresholds are in `config/guardsConfig.json`.

## Application Overview

Prerequisites: 
- Nodejs 14+
- haproxy
- mongodb 4+
- certbot
- letsencrypt


Install FDM dependencies (Ubuntu/CentOS/Redhat):

```bash
cd Flux

npm install
```

To run this as Production:

```bash
npm start
```

Application will run on port 16130

## Guide for ubuntu 20.04

    sudo apt update
    sudo apt upgrade
    sudo apt-get install software-properties-common certbot haproxy curl git wget screen -y
    wget -qO- https://raw.githubusercontent.com/nvm-sh/nvm/v0.38.0/install.sh | bash
    export NVM_DIR="$([ -z "${XDG_CONFIG_HOME-}" ] && printf %s "${HOME}/.nvm" || printf %s "${XDG_CONFIG_HOME}/nvm")"
    [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh" # This loads nvm
    nvm install 14
    nvm use 14
    wget -qO - https://www.mongodb.org/static/pgp/server-4.4.asc | sudo apt-key add -
    echo "deb [ arch=amd64,arm64 ] https://repo.mongodb.org/apt/ubuntu focal/mongodb-org/4.4 multiverse" | sudo tee /etc/apt/sources.list.d/mongodb-org-4.4.list
    sudo apt-get update
    sudo apt-get install -y mongodb-org
    sudo systemctl start mongod
    sudo systemctl daemon-reload
    sudo systemctl enable mongod

Update haproxy

    nano /etc/haproxy/haproxy.cfg

Paste this under all:

    frontend wwwhttp
            bind 0.0.0.0:80
            option forwardfor except 127.0.0.0/8
            http-request add-header X-Forwarded-Proto http

            acl letsencrypt-acl path_beg /.well-known/acme-challenge/
            use_backend letsencrypt-backend if letsencrypt-acl
            default_backend letsencrypt-backend

    backend letsencrypt-backend
            server letsencrypt 127.0.0.1:8787

Reload haproxy

    sudo service haproxy reload

Update crontab

    sudo nano /etc/cron.d/certbot

Comment all other lines and paste this:

    0 0 1 * * root bash /opt/update-certs.sh

Clone and run FDM

    git clone https://github.com/runonflux/flux-domain-manager
    cd flux-domain-manager/
    npm i
    screen -S FDM
    npm start

**Final words**

FDM is updating /opt/update-certs.sh file automatically with following content

    #!/usr/bin/env bash

    # Renew the certificate
    certbot renew --force-renewal --http-01-port=8787 --preferred-challenges http

    # Concatenate new cert files, with less output (avoiding the use tee and its output to stdout)
    bash -c "cat /etc/letsencrypt/live/rosetta.runonflux.io/fullchain.pem /etc/letsencrypt/live/rosetta.runonflux.io/privkey.pem > /etc/ssl/rosetta.runonflux.io/rosetta.runonflux.io.pem"

    # Reload  HAProxy
    service haproxy reload
